# 数学建模竞赛新题求解 RAG 知识库

本知识库以 CUMCM 2000—2025 A/B/C 逐问库为底座，并纳入深圳杯、MathorCup、电工杯、五一数学建模竞赛和中国研究生数学建模竞赛（华为杯）的高复用精选题。首要目标不是查询“某年某题用了什么算法”，而是辅助解决新的数学建模题：识别数学结构、召回历史类比、形成候选算法、补齐建模流程，并主动检查假设、评价指标、灵敏度、写作证据链和常见失分点。

## 知识结构

- `case_subquestion`：261 条历史逐小问知识块。
- `problem_overview`：78 条整题任务链与结构画像。
- `algorithm_card`：24 条算法知识卡。
- `strategy_card`：面向新题求解的通用策略卡。
- 跨赛精选：21 套来源分级、质量评分和逐问提炼的高复用题，覆盖五类赛事。
- 专题扩展：包含 2025 深圳杯 B 题的色域映射、多基色显示、逐像素校正和颜色工程审计卡。
- 通用范式：来源审计、任务依赖、假设、评价、灵敏度和论文写作卡。

每个知识块均包含标题、正文、标签、优先级及结构化元数据：问题类型、领域、候选算法、建模流程、模型假设、评价指标、灵敏度、论文写作范式、注意事项、来源等级和质量分。

筛选规则、21套清单与排除记录见 `CROSS_CONTEST_SELECTION.md`。

## 快速使用

从 `mathmodel-rag` Skill 目录运行：

```powershell
python scripts/retrieve_modeling_kb.py "需要预测未来销量，并在仓容约束下制定补货计划" --top-k 12 --format prompt
```

常用输出格式：

- `prompt`：生成可直接交给大模型的上下文包。
- `brief`：查看简短召回排名。
- `json`：供程序或 Agent 工作流调用。

写入文件：

```powershell
python scripts/retrieve_modeling_kb.py "多目标车辆路径与时间窗" --format prompt --out retrieved_context.md
```

完整性与召回测试：

```powershell
python <plugin-root>/scripts/validate_bundle.py
```

验证程序检查插件结构、JSONL、SQLite、索引数量、元数据完整性、模板配对和复合新题召回。

## 检索机制

默认检索不依赖联网、API Key 或第三方模型，使用中文字符二/三元组 BM25、查询意图扩展、字段加权、来源/质量优先级和知识块类型配额。这样可以同时召回：

1. 最相关的历史小问；
2. 可迁移的整题结构；
3. 对应算法知识卡；
4. 验证与竞赛落地策略。

`chunks.jsonl` 可直接导入 Chroma、FAISS、Milvus、Qdrant、Elasticsearch 或其他向量数据库。若后续接入中文嵌入模型，建议对 `title + content + tags` 生成向量，同时保留 `year/problem/problem_type/domain` 做元数据过滤，并与当前稀疏分数做混合排序。

## 推荐查询写法

查询中尽量同时包含：

- 背景对象；
- 小问核心任务；
- 数据形态，例如时间序列、表格、图像或空间坐标；
- 目标，例如预测、分类、排序或优化；
- 关键约束，例如容量、时间窗、概率风险或安全阈值。

只输入“2024C”适合查历史题；输入“销量存在波动，需要在轮作、产量和价格约束下制定多年计划”更适合辅助解决新题。

## 重要边界

- 算法条目是推荐候选组合，不是唯一官方答案。
- 历史题只能作为结构类比，最终模型必须由新题变量、约束、数据和验证结果决定。
- 网络资料须记录来源等级：官方题面/评审总结优先，获奖名单不能替代获奖论文全文；无法核验获奖身份的论文只作参考解法。
- 数学建模通常没有唯一官方答案；库内“官方优先”指官方题面、官方赛后解析、官方公开优秀论文和可核验获奖身份优先，不虚构标准解。
- 2000—2018 年 C 题保留用于扩展检索，但应注意其历史组别口径。
